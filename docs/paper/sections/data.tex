\section{Data}
\label{sec:data}

\subsection{Data source and variables}
\label{sec:data-source}
The dataset comes from the Kaggle competition \emph{Give Me Some Credit}
\citep{kaggle2011givemesomecredit}. The labelled file has 150{,}000 clients,
ten numerical features (Table~\ref{tab:variables}) and the binary target
\texttt{SeriousDlqin2yrs}, equal to 1 when the client was 90 days or more past
due within two years. Only 10{,}026 clients (6.7\%) are positive. The
competition's second file (101{,}503 clients) has no labels, so every result in
this paper comes from the labelled file; the unlabelled file is used only for
an optional competition submission.

\subsection{Data quality and preprocessing}
\label{sec:preprocessing}
The exploratory analysis found five problems, each handled by a fixed rule
that looks only at the row itself:
\begin{enumerate}
  \item \emph{Impossible age.} One client has age 0; it is set to missing.
  \item \emph{Revolving utilization.} The ratio should be close to 1 at most,
  and 99\% of clients are below 1.1, but the maximum is 50{,}708. Values above
  4 (400\% of the limit; 264 clients) are treated as recording errors.
  \item \emph{Special codes in the late-payment counts.} The three counts jump
  from at most 17 to the values 96 and 98. These 269 clients have the codes in
  all three columns at once and a default rate of 54.6\%, so the codes are not
  counts but a separate signal. They are set to missing and flagged.
  \item \emph{Debt ratio without income.} Monthly income is missing for 29{,}731
  clients (19.8\%). For them the median debt ratio is 1{,}159, against 0.30 for
  the others, which suggests the ratio was computed without an income
  (an absolute debt). The debt ratio is set to missing whenever income is
  missing.
  \item \emph{Missing dependents.} 3{,}924 clients have no number of
  dependents; all of them also lack income.
\end{enumerate}
Missing values turned out to be informative: clients without income default
\emph{less} often than the others (5.6\% against 6.9\%). Imputing them alone
would erase this signal, so four binary flags are added (income missing,
dependents missing, late-payment codes 96/98, revolving utilization above
400\%) before the remaining gaps are filled with the training median.
Figure~\ref{fig:eda} summarizes the main relationships with the target.

The steps differ in whether they learn from the data. The five rules and the
flags are row-wise and learn nothing, so they can be applied anywhere. The
median imputation, the standardization and the models do learn statistics
from the data, and are therefore fitted only on the training folds of each
cross-validation round, inside a scikit-learn pipeline
\citep{pedregosa2011scikit}. Fitting them on all rows before splitting would
leak information from the validation rows into training (\emph{door~1} of
leakage in \citealp{oku2026slides}). For the logistic regression only, the
nine long-tailed features (skewness above 80 for income and debt ratio) are
replaced by $\log(1+x)$ and all numerical features are standardized, so that
the penalty compares coefficients on a common scale; the flags stay as 0/1.

We also tried hand-made features. A weighted sum of the three late-payment
counts had the highest correlation with the target (0.36, against 0.31 for the
best single count), but it is an exact linear combination of columns already
in the model: for a linear model it adds no information and makes the design
matrix rank-deficient \citep{oku2026slides}. The ratios we tried were either
weaker than the feature they came from or almost uncorrelated with the
target, so none was kept.
